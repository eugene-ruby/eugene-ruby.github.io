Когда запросы становятся медленными, а лог растёт на десятки строк, стоит проверить, как загружаются ассоциации. Разберёмся, чем отличаются `joins`, `includes`, `preload` и `eager_load` в ActiveRecord. SQL ниже схематичный: точный запрос зависит от схемы и условий.

---

## 🤝 joins

Создаёт SQL JOIN, но **сам по себе не загружает связанные записи в ассоциацию**.

```ruby
User.joins(:company).where(companies: { active: true })
```

🔎 SQL:

```sql
SELECT "users".* FROM "users"
INNER JOIN "companies" ON "companies"."id" = "users"."company_id"
WHERE "companies"."active" = TRUE
```

* Позволяет фильтровать пользователей по полям компании.
* Если ассоциация не загружена другим способом, обращение к `user.company` вызовет отдельный запрос. При обходе списка пользователей это может привести к N+1.

---

## 📦 includes

Подгружает ассоциации, чтобы избежать N+1:

```ruby
User.includes(:company).each { |u| puts u.company.name }
```

Пример предполагает, что у каждого пользователя есть компания. Без условий по полям ассоциации ActiveRecord обычно выполняет отдельные запросы:

```sql
SELECT "users".* FROM "users";
SELECT "companies".* FROM "companies" WHERE "companies"."id" IN (...)
```

Способ загрузки зависит от запроса: если условия требуют обращения к таблице ассоциации, `includes` может использовать `LEFT OUTER JOIN` вместо отдельного `SELECT`. Для SQL-условия строкой может потребоваться явно указать `references(:company)`.

---

## 🚚 preload

Загружает ассоциации **отдельным запросом**, когда основной запрос выполняется:

```ruby
User.preload(:company)
```

🔎 SQL:

```sql
SELECT "users".* FROM "users";
SELECT "companies".* FROM "companies" WHERE "companies"."id" IN (...)
```

* Не добавляет JOIN для загрузки ассоциации.
* Удобен, когда нужны связанные записи, но не нужно использовать их таблицу в условиях основного запроса. Если фильтровать по её полям всё же нужно, `preload` можно сочетать с `joins`.

---

## 🔍 eager\_load

Загружает ассоциации через `LEFT OUTER JOIN` одним запросом:

```ruby
User.eager_load(:company).where(companies: { name: "Acme" })
```

🔎 SQL:

```sql
SELECT "users"."id" AS t0_r0, "users"."name" AS t0_r1, ...,
       "companies"."id" AS t1_r0, "companies"."name" AS t1_r1, ...
FROM "users"
LEFT OUTER JOIN "companies" ON "companies"."id" = "users"."company_id"
WHERE "companies"."name" = 'Acme'
```

* Ассоциации загружаются вместе с основными записями.
* Для ассоциаций с несколькими записями JOIN может увеличить число строк результата, поэтому один SQL-запрос не обязательно выгоднее нескольких.

---

## 💡 Когда использовать что

| Задача | Метод |
| --- | --- |
| Нужно фильтровать по полям ассоциации, но не загружать её записи | `joins` |
| Нужно избежать N+1 без явного выбора способа загрузки | `includes` |
| Нужно загрузить ассоциации отдельным запросом | `preload` |
| Нужно загрузить ассоциации через JOIN | `eager_load` |

🔚 **Вывод**: выбирай метод по тому, нужны ли записи ассоциации в памяти и должна ли её таблица участвовать в основном запросе. `preload` предсказуем в способе загрузки, но не заменяет `joins` для фильтрации; `includes` удобен, когда отдельные запросы и JOIN оба допустимы.
