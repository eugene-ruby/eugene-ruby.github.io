Ruby 3.x развивает язык сразу в нескольких направлениях: параллельное выполнение, асинхронный ввод-вывод, JIT-компиляция и более компактный синтаксис. Ниже — краткая шпаргалка по версиям от 3.0 до 3.4 и изменениям, на которые стоит обратить внимание при обновлении.

## 🧾 Ruby 3.0 (декабрь 2020)

* **Ractor** появился как экспериментальный механизм параллельного выполнения. Объекты нельзя свободно разделять между Ractor: при передаче данных нужно учитывать правила их совместного использования и перемещения.
* **Fiber Scheduler API** дал библиотекам основу для неблокирующего ввода-вывода внутри потоков. Сам по себе он не превращает любой код в асинхронный.
* Развивалось сопоставление с образцом — **pattern matching**, появившееся в Ruby 2.7.
* Продолжилась работа над **MJIT**.
* Разделение позиционных аргументов и именованных параметров стало строгим. Код, который раньше неявно передавал последний хеш как именованные параметры, при обновлении может потребовать явной передачи через `**`.

Цель *Ruby 3x3* — трёхкратное ускорение относительно Ruby 2.0 — не означает, что каждое приложение на Ruby 3.0 работает втрое быстрее.

---

## ⚙️ Ruby 3.1 (декабрь 2021)

* Появился **YJIT** — на тот момент экспериментальный JIT-компилятор, который нужно было включать отдельно.
* Сократилась запись хеша, если имя ключа совпадает с именем локальной переменной: `{name:}` вместо `{name: name}`.
* В поставку вошёл гем **`debug`** с возможностями интерактивной отладки. Называть его экспериментальной возможностью языка не стоит.

---

## 🧰 Ruby 3.2 (декабрь 2022)

* Появился `Data` — базовый класс для объектов-значений с фиксированным набором полей. Экземпляр нельзя изменить через его поля, но объекты внутри полей **не становятся неизменяемыми автоматически**.
* Экземпляр `Data` можно совместно использовать между Ractor, только если значения его полей тоже допускают совместное использование.
* **YJIT** перестал считаться экспериментальным, но не стал включаться по умолчанию.
* **MJIT** был переработан. Это отдельный JIT-компилятор, не новая версия YJIT.

---

## 🚀 Ruby 3.3 (декабрь 2023)

* **YJIT** получил дальнейшие улучшения производительности и использования памяти. Он по-прежнему не включается автоматически для всех приложений.
* Появился **Prism** — новый парсер Ruby.
* Экспериментальный **RJIT** заменил MJIT. Это не означает, что для ускорения приложения обязательно нужно выбирать один из JIT-компиляторов.

---

## 🔬 Ruby 3.4 (декабрь 2024)

* **Prism** стал парсером по умолчанию. Если инструменты разработки зависят от особенностей разбора кода, их совместимость стоит проверить при обновлении.
* Появился `it` — неявное имя единственного параметра блока. Оно помогает сократить простые блоки, но не всегда делает сложный блок понятнее.
* Продолжилось развитие **YJIT**. Ускорение конкретного приложения нельзя определить по номеру версии: его нужно измерять на собственной нагрузке.
* Изменилось распределение части стандартных библиотек между *default gems* и *bundled gems*. Если приложение использует такую библиотеку, укажите зависимость явно в `Gemfile` или gemspec, вместо того чтобы рассчитывать на её присутствие в окружении.

---

## 💡 Общие тренды Ruby 3.x

| Направление | Что изменилось |
| --- | --- |
| Производительность | Развивались JIT-компиляторы, прежде всего YJIT. Результат зависит от приложения. |
| Параллелизм и ввод-вывод | Ractor даёт модель параллельного выполнения с ограничениями на обмен объектами; Fiber Scheduler помогает организовать неблокирующий ввод-вывод. Это разные задачи. |
| Синтаксис и данные | Развивалось pattern matching, появились сокращённая запись хеша, `Data` и `it` для блоков. |
| Совместимость | Изменились правила передачи именованных параметров, инструменты разбора кода и состав зависимостей некоторых стандартных библиотек. |

При переходе между версиями прежде всего проверьте места передачи именованных параметров, зависимости от стандартных библиотек и инструменты, работающие с синтаксисом Ruby. Ractor, Fiber Scheduler и YJIT полезны для разных задач — подключать их все только потому, что они появились в Ruby 3.x, не нужно.
