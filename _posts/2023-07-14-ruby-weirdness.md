Ruby — выразительный язык, но некоторые его правила легко понять неправильно. Разберём, чем ложность отличается от равенства, что показывают `object_id` и `frozen?` и в каком контексте выполняются разные виды `eval`.

---

## ❓ false == nil?

```ruby
false == nil     # => false
!nil             # => true
!!nil            # => false
```

* В Ruby только `false` и `nil` считаются ложными значениями.
* При этом они не равны между собой: проверка значения в условии и сравнение через `==` — разные операции.

---

## 🔍 object\_id и литералы

```ruby
:foo.object_id == :foo.object_id   # => true
"foo".object_id == "foo".object_id # => false
42.object_id == 42.object_id       # => true
```

Одинаковое написание литералов не всегда означает один и тот же объект. Символ `:foo` сохраняет идентичность при повторном обращении, а каждое вычисление строкового литерала `"foo"` в этом примере создаёт отдельный объект. Целое число `42` также даёт одинаковый `object_id` при повторном обращении. Но обобщать это на все числа или считать, что строки никогда не могут разделять объект, нельзя.

---

## ❄️ frozen по умолчанию?

```ruby
42.frozen?     # => true
:foo.frozen?   # => true
nil.frozen?    # => true
true.frozen?   # => true
```

Эти значения неизменяемы; то же относится к `false` и встроенным числовым значениям, таким как `Integer` и `Float`. Но это не значит, что любой объект числового класса или любая строка заморожены.

---

## 🧠 eval, class\_eval, instance\_eval

```ruby
class User; end
obj = Object.new

eval("1 + 2")                         # => 3
User.class_eval { def x; 42; end }
obj.instance_eval { def y; 99; end }

User.new.x # => 42
obj.y      # => 99
```

Здесь различается контекст выполнения:

* `eval` выполняет строку кода в текущем контексте, а не обязательно в глобальном. Передавать ему недоверенную строку опасно: она может выполнить произвольный Ruby-код.
* `class_eval` выполняет блок в контексте `User`. Определённый через `def x` метод становится методом экземпляров этого класса.
* `instance_eval` выполняет блок с `self`, равным `obj`. Определённый здесь `y` становится методом только этого объекта.

---

🔚 **Вывод:** одинаковое поведение в условии не означает равенства объектов, а одинаковый текст литералов не всегда означает одинаковую идентичность. С `eval` и его вариантами важно понимать, какой код выполняется и в каком контексте.
