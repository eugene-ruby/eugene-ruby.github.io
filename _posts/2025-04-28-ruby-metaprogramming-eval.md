Ruby даёт доступ к контексту выполнения и позволяет удобно встраивать действия в цепочки вызовов. Разберём три разных инструмента — `eval`, `binding` и `Kernel#tap`: что они делают, где помогают и какие ошибки легко допустить.

---

## 🔮 `eval` — магия с последствиями

**Что это?**  
Метод `eval` выполняет строку как Ruby-код и возвращает результат этого кода. Если передать ему `binding`, код получит доступ к захваченному контексту. В отличие от `require`, `eval` не загружает файл как библиотеку.

### 💼 Пример: динамические условия
```ruby
filters = { min_price: 100, category: "books" }
query = Product.all

filters.each do |key, value|
  query = query.where(eval("#{key} = ?"), value) # Так не сработает
end
```

**Проблема:** строка `"min_price = ?"` не является корректным Ruby-кодом, поэтому `eval` вызовет ошибку синтаксиса. Кроме того, `min_price` здесь должен задавать нижнюю границу цены, а не равенство. Если подставлять пользовательский ввод в строку для `eval`, он может превратиться в исполняемый Ruby-код. Это отдельный риск, не тождественный SQL-инъекции.

### ✅ Безопасная альтернатива
```ruby
filters = { min_price: 100, category: "books" }
query = Product.all

query = query.where("price >= ?", filters[:min_price]) if filters.key?(:min_price)
query = query.where(category: filters[:category]) if filters.key?(:category)
```

Здесь пример предполагает, что у `Product` есть столбцы `price` и `category`. Условия задаются для известных полей, а значения передаются через интерфейс `where`, без сборки SQL из пользовательского ввода. Если поля фильтра выбираются динамически, их тоже нужно ограничить разрешённым набором: параметризация значений не делает произвольное имя столбца безопасным.

### 🧨 Когда НЕ использовать:
- Для выполнения строк, полученных от пользователя.
- Для разбора JSON или XML: нужны соответствующие парсеры, например `JSON.parse` для JSON.
- Для создания методов, когда задачу решает `define_method`.

**Вывод:** используйте `eval` только для доверенного кода, когда более узкого инструмента недостаточно.

## 🕵️‍♂️ `binding` — замочная скважина в контекст

**Что это?**  
`binding` возвращает объект `Binding`, который сохраняет доступ к текущему контексту: локальным переменным, методам и `self`. Это не неизменяемый снимок значений: через `Binding` можно обращаться к переменным захваченного контекста.

### 💼 Пример: отладка сложных методов
```ruby
require "irb"

def calculate_discount(user, items)
  discount = 0
  # ... логика расчёта ...
  binding.irb # Открыть интерактивную консоль в этом месте
  apply_discount(discount)
end
```

**Как работает:** в интерактивной консоли можно проверить доступные здесь локальные переменные. Такой вызов стоит убрать после отладки; в приложении также учитывайте, что консоль даёт доступ к данным текущего контекста.

### 🛠 Практическое применение:
1. **Динамические шаблоны** (ERB):
```ruby
require "erb"

template = ERB.new("Привет, <%= name %>!")
name = "Антон"
template.result(binding) #=> "Привет, Антон!"
```

ERB исполняет Ruby-код из шаблона, поэтому не передавайте в него шаблон из недоверенного источника без соответствующей изоляции.

2. **Доступ к локальным переменным контекста:**
```ruby
user = create(:user, name: "Test User")
b = binding
b.local_variable_get(:user).name #=> "Test User"
```

Для обычного теста доступ через `binding` избыточен: проще проверить `user.name` напрямую. Возможность получить локальную переменную полезна инструментам отладки и метапрограммирования.

**Вывод:** `binding` помогает исследовать контекст выполнения и передавать его инструментам вроде ERB. Если сохранять объект `Binding` надолго, он может удерживать доступные через него объекты в памяти.

## 🚰 `Kernel#tap` — труба для объектов

**Что это?**  
Метод `tap` передаёт объект в блок и возвращает тот же объект независимо от результата блока. Это позволяет выполнить действие посреди цепочки вызовов, не заменяя её промежуточное значение.

### 💼 Пример: отладка цепочек
```ruby
User.active
  .tap { |users| puts "SQL: #{users.to_sql}" }
  .limit(10)
```

Здесь `tap` оставляет в цепочке отношение Active Record, а `to_sql` показывает сформированный запрос без его выполнения. Напротив, вызов `count` внутри блока отправил бы отдельный запрос к базе данных.

### 🏗 Паттерн: инициализация с побочными эффектами
```ruby
def create_config
  Config.new.tap do |c|
    c.set_defaults
    c.connect!
    Rails.logger.info "Config initialized"
  end
end
```

`tap` вернёт созданный объект. Этот вариант уместен, если вызывающему коду нужен именно объект `Config`, а побочные действия блока ожидаемы. Сам по себе `Config.new` не означает, что объект сохранён в базе данных.

### ❌ Антипаттерн:
```ruby
# Ошибка, если вызывающему коду нужен результат update
user.tap do |u|
  u.update(role: :admin) # update вернёт true/false, но tap вернёт user
end
```

Если нужно проверить успех операции, используйте `user.update(role: :admin)` напрямую. Если нужен объект после успешного обновления, можно использовать `user.tap { |u| u.update!(role: :admin) }`: при ошибке сохранения `update!` вызовет исключение.

**Вывод:** `tap` подходит для отладки цепочек и действий над объектом, после которых нужно вернуть тот же объект. Учитывайте побочные эффекты блока: они не меняют возвращаемое значение `tap`, но могут менять состояние объекта или обращаться к внешним ресурсам.

## 🧪 Сравнительная таблица

| Метод | Что возвращает | Влияние на состояние | Основной риск |
|-------|----------------|----------------------|---------------|
| `eval` | Результат выполненного кода | Зависит от кода | Выполнение недоверенного кода |
| `binding` | Объект `Binding` | Сам вызов ничего не меняет; через объект доступен контекст | Доступ к чувствительным данным, удержание объектов в памяти |
| `tap` | Исходный объект | Блок может изменить объект или вызвать побочный эффект | Незаметный результат операции внутри блока |

---

## 🎯 Когда что применять?

1. **`eval`** — когда действительно нужно выполнить доверенный Ruby-код из строки и более узкого инструмента недостаточно.
2. **`binding`** — для отладки и передачи контекста инструментам вроде ERB.
3. **`tap`** — когда нужно выполнить действие посреди цепочки или настроить объект, сохранив его возвращаемым значением.

---

## 🚨 Главное правило

Риски у этих методов разные. Перед использованием спросите:
- Для `eval`: доверяю ли я строке с кодом и можно ли обойтись без её выполнения?
- Для `binding`: кому станет доступен контекст и как долго он будет удерживаться?
- Для `tap`: нужен ли вызывающему коду исходный объект, а не результат действия в блоке?
