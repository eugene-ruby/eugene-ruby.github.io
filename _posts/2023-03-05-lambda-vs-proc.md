В Ruby блок можно вызвать через `yield` или получить как объект `Proc`. При этом lambda и обычный proc по-разному обрабатывают аргументы и `return`. Разберём эти различия на примерах.

---

## 🧠 Три способа вызвать блок кода

```ruby
def with_yield
  yield
end

def with_proc(p)
  p.call
end

with_yield { puts "через yield" }         # => через yield
with_proc(Proc.new { puts "через proc" }) # => через proc
```

---

## 🤹‍♂️ Различия между lambda и Proc.new

### 1. Поведение `return`

```ruby
def l
  f = lambda { return "lambda" }
  f.call
  "после lambda"
end

def p
  f = Proc.new { return "proc" }
  f.call
  "после proc"
end

puts l # => после lambda
puts p # => proc
```

В lambda `return` завершает только её вызов, поэтому метод `l` продолжает выполняться. В обычном proc `return` выходит из метода, в котором proc был создан: строка `"после proc"` не выполнится.

Это работает, пока создавший proc метод ещё выполняется. Если сохранить proc и вызвать его после завершения этого метода, Ruby поднимет `LocalJumpError`: возвращаться уже некуда.

---

### 2. Проверка аргументов

```ruby
l = ->(x, y) { "#{x}, #{y}" }
p = Proc.new { |x, y| "#{x}, #{y}" }

puts l.call(1)         # ArgumentError
puts p.call(1)         # => 1,
```

Lambda проверяет количество аргументов. Обычный proc в этом примере подставляет `nil` вместо недостающего аргумента; при интерполяции он превращается в пустую строку.

---

## 🚀 Синтаксис

```ruby
lambda { }             # lambda
->(x, y) { x + y }      # сокращённая запись lambda
Proc.new { }           # обычный proc
proc { }               # ещё один способ создать обычный proc
```

`->` удобно использовать для краткой записи lambda. Выбор между lambda и обычным proc зависит не только от синтаксиса: у них различаются обработка аргументов и поведение `return`.

---

## 🧷 А `yield`?

* Вызывает блок, переданный методу, без явного параметра `&block`.
* Если блока нет, вызов `yield` поднимет `LocalJumpError`. Когда блок необязателен, это можно проверить через `block_given?`.

```ruby
def do_something
  yield if block_given?
end

do_something { puts "Окей!" }
```

`yield` не задаёт собственных правил для `return` и аргументов: поведение зависит от переданного блока. Например, `return` в обычном блоке выходит из метода, в котором блок определён, а не обязательно из метода, вызывающего `yield`.

---

## 📌 Практика VS собеседование

| Характеристика | lambda | Proc.new | yield |
| --- | --- | --- | --- |
| `return` внутри | завершает вызов lambda | выходит из метода, где proc создан | зависит от переданного блока |
| Аргументы | проверяются строго | обрабатываются гибко | зависят от переданного блока |
| Доступен как объект `Proc`? | да | да | нет, если не получить блок через `&block` |
| Можно сохранить в переменную? | да | да | не сам `yield`; блок можно получить через `&block` |

---

## 💡 Совет: называй блок, если нужен объект Proc

```ruby
def wrap(&block)
  block.call if block
end
```

Если нужно только вызвать переданный блок, достаточно `yield`; для необязательного блока можно добавить `block_given?`. Параметр `&block` нужен, когда блок требуется сохранить, передать дальше или вызвать как объект.

## Доступен как объект?

### 🔹 `lambda` и `Proc.new`:

Оба способа создают объекты `Proc`, которые можно сохранить в переменной и вызвать позже:

```ruby
f = lambda { puts "Hi" }
f.call
```

```ruby
p = Proc.new { puts "Hello" }
p.call
```

`f` и `p` — имена переменных, а не имена самих объектов.

---

### 🔸 `yield`:

`yield` вызывает переданный методу блок, но не создаёт переменную для обращения к нему:

```ruby
def greet
  yield if block_given?
end

greet { puts "Yo" }
```

Если блоку нужен доступ как к объекту, укажи параметр `&block`:

```ruby
def greet(&block)
  block.call if block
end
```

---

### 💡 Резюме:

* **lambda** и **proc** создают объекты `Proc`, которые можно сохранить и передать дальше; главное различие между ними — обработка аргументов и `return`.
* **yield** вызывает переданный блок без переменной для него. Если нужен объект `Proc`, используй `&block`.

---

🔚 Вывод: `lambda` и обычный proc похожи по форме, но `return` внутри них может изменить ход выполнения по-разному. `yield` же вызывает переданный блок — и его поведение зависит от этого блока.
