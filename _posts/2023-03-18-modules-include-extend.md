Ruby позволяет добавлять поведение через модули несколькими способами. Разберём, где окажутся методы после `include`, `extend` и `prepend`, а также почему `refine` не работает как глобальный патч.

---

## 🧩 `include`: добавляем методы как instance-методы

```ruby
module Speak
  def hello
    "Привет!"
  end
end

class Human
  include Speak
end

puts Human.new.hello # => Привет!
```

**`include`** добавляет модуль в цепочку поиска методов экземпляра. Поэтому `Speak#hello` доступен у `Human.new`, но не становится методом класса `Human`.

---

## 🧠 `extend`: добавляем методы как методы самого объекта

```ruby
module Meta
  def version
    "1.0"
  end
end

class App
  extend Meta
end

puts App.version # => 1.0
```

**`extend`** делает методы модуля доступными у конкретного объекта. Здесь этот объект — класс `App`, поэтому `version` вызывается как метод класса.

---

## 🔄 `prepend`: модуль перед классом в цепочке поиска

```ruby
module Loud
  def hello
    "ЭТО ПРЕПЕНД!"
  end
end

class Robot
  prepend Loud

  def hello
    "Привет от робота"
  end
end

puts Robot.new.hello # => ЭТО ПРЕПЕНД!
```

**`prepend`** вставляет модуль **перед** классом в цепочке `ancestors`. Поэтому поиск `hello` находит метод из `Loud` раньше метода из `Robot`:

```ruby
puts Robot.ancestors
# => [Loud, Robot, Object, Kernel, BasicObject]
```

В этом примере `Loud#hello` полностью заменяет результат `Robot#hello`. Если нужно сохранить исходное поведение, вызывай `super` из метода в подключённом модуле.

---

## 🗺️ Где `include`, где `extend`?

| Что подключаем | Куда подключаем | Где будет доступен метод |
| -------------- | --------------- | ----------------------- |
| `include M` | В класс | У экземпляров класса |
| `extend M` | В класс | У самого класса |
| `extend M` | В объект | У этого объекта |
| `prepend M` | В класс | У экземпляров; метод модуля ищется раньше метода класса |

## 🤯 `using` и `refine` — локальные патчи

Иногда хочется изменить поведение существующего класса, но **не глобально**. Для этого можно использовать `refine`:

```ruby
module Shout
  refine String do
    def shout
      upcase + "!!!"
    end
  end
end

using Shout

puts "ruby".shout # => RUBY!!!
```

`using Shout` активирует уточнение в текущей лексической области для кода ниже этой строки. Оно не добавляет `shout` ко всем строкам во всей программе: код в другой области сам по себе этот метод не увидит. Поэтому `refine` не поможет, если вызов, который нужно изменить, находится внутри стороннего кода, где уточнение не активировано.

## 🔥 Пример подвоха на собеседовании

```ruby
module M
  def greet
    "hello from M"
  end
end

class A
  include M
end

class B
  extend M
end

puts A.new.greet    # => ?
puts B.greet        # => ?
```

**Ответ:** оба вызова выведут `hello from M`.

* `A.new.greet` работает: `include` добавил метод в цепочку поиска для экземпляров `A`.
* `B.greet` работает: `extend` сделал метод доступным у объекта `B`.
* `A.greet` и `B.new.greet`, если их добавить в пример, вызовут `NoMethodError`.

## ❗ Совет на прод

Если пишешь модуль, выбирай механизм по тому, где должен работать его метод:

* `include` — когда поведение нужно **экземплярам** класса.
* `extend` — когда метод нужен **конкретному объекту**, в том числе объекту-классу. `extend self` внутри модуля позволяет вызывать методы модуля на самом модуле.
* `prepend` — когда нужно перехватить вызов **перед** методом класса. Вызывай `super`, если нужно продолжить цепочку, а не заменить поведение полностью.
* `refine` — когда изменение должно действовать только в подходящей **лексической области**, а не глобально.

---

🔚 **Вывод:** выбор зависит не только от того, какой модуль подключаешь, но и от того, **где Ruby будет искать его методы**: у экземпляра, у конкретного объекта или в области действия уточнения.
