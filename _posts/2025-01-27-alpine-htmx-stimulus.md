Современный фронтенд часто ассоциируется с React, Vue и Angular. Но если Rails уже рендерит страницы на сервере, для меню, форм и подгрузки контента может хватить небольшого количества JavaScript. Разберёмся, когда выбрать Alpine.js или Stimulus, что делает htmx и как эти инструменты сочетаются с серверным рендерингом.

---

## 🕰️ Всё началось с jQuery... а потом стало сложно

Помните времена, когда для анимации кнопки хватало трёх строк jQuery? Фреймворки дали больше возможностей для сложных интерфейсов, но их возможности нужны не каждому проекту.

Если приложение в основном отдаёт готовый HTML, не обязательно строить отдельный SPA-фронтенд. Можно добавить интерактивность там, где она нужна, и оставить рендеринг страниц на стороне Rails. Alpine.js, htmx и Stimulus подходят для разных частей этой задачи. Они работают с HTML, который возвращает сервер, а способ их подключения зависит от настройки проекта.

---

## 🧩 Кому что подходит?

| Инструмент   | Для чего?                       | Пример использования         |
|--------------|--------------------------------|------------------------------|
| **Alpine.js** | Локальная интерактивность      | Раскрывающиеся меню, модалки |
| **htmx**     | Запросы с подстановкой HTML    | Формы, пагинация             |
| **Stimulus** | Логика элементов страницы      | Сортировка таблиц, валидация |

## 🌲 Alpine.js: «React на минималках»

Alpine.js добавляет реактивное поведение прямо в разметку. Это не замена React для приложения со сложным клиентским состоянием, зато удобный вариант для небольшого интерактивного фрагмента.

### Код примера: аккордеон
```html
<div x-data="{ open: false }">
  <button type="button" @click="open = !open">Развернуть</button>
  <div x-show="open" x-transition>
    Содержимое аккордеона...
  </div>
</div>
```

**Плюсы:**
- Для такого примера не нужна сборка.
- Поведение задаётся рядом с разметкой через атрибуты (`x-data`, `x-show`).
- Удобен для небольших независимых элементов интерфейса.

**Ограничения:**
- Если логики в атрибутах становится много, разметку трудно читать и тестировать. Её можно вынести в отдельный компонент через `Alpine.data`.
- Состояние в `x-data` ограничено областью компонента, но обмен данными между несколькими компонентами потребует отдельного решения.

**Когда брать?**  
Для локальной интерактивности, когда состояние и поведение удобно держать рядом с HTML.

## 🧩 htmx: AJAX без собственного JavaScript

htmx — JavaScript-библиотека, но для типового запроса не нужно писать обработчик `fetch` вручную. Сервер возвращает HTML, который htmx вставляет в указанный элемент.

### Пример: подгрузка комментариев
```html
<button type="button" hx-get="/comments" hx-target="#comments-list">
  Загрузить комментарии
</button>
<div id="comments-list"></div>
```

Здесь `/comments` должен вернуть HTML-фрагмент со списком комментариев. По умолчанию htmx заменит содержимое `#comments-list` полученным ответом.

**Плюсы:**
- Можно использовать серверные шаблоны вместо отдельного JSON API для этого фрагмента.
- Запрос и место вставки ответа описаны в HTML.
- Для SSE и WebSocket есть отдельные расширения; это разные механизмы, один не работает «через» другой.

**Ограничения:**
- Нужен серверный маршрут, который возвращает подходящий HTML.
- Сложное клиентское состояние всё равно потребует JavaScript.
- Если проект уже использует Turbo, стоит разграничить, какой инструмент обрабатывает конкретные запросы и обновляет конкретные элементы. Ответ Turbo Streams не становится ответом для htmx автоматически.

**Когда брать?**  
Когда сервер уже умеет рендерить нужный фрагмент и хочется обновлять часть страницы без собственного кода для запроса и вставки HTML.

## 🎮 Stimulus: «jQuery на стероидах»

Stimulus связывает HTML с JavaScript-контроллером. Вместо поиска элементов по всей странице контроллер работает со своим элементом и объявленными целями.

### Пример: кнопка «Нравится»
```javascript
// likes_controller.js
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static targets = ["counter"]

  async like() {
    const token = document.querySelector('meta[name="csrf-token"]')?.content

    try {
      const response = await fetch("/likes", {
        method: "POST",
        headers: {
          "Accept": "application/json",
          "X-CSRF-Token": token
        }
      })

      if (!response.ok) throw new Error(`HTTP ${response.status}`)

      const data = await response.json()
      this.counterTarget.textContent = data.count
    } catch (error) {
      console.error("Не удалось поставить лайк", error)
    }
  }
}
```

```html
<div data-controller="likes">
  <button type="button" data-action="likes#like">❤️</button>
  <span data-likes-target="counter">0</span>
</div>
```

Пример предполагает, что контроллер `likes` зарегистрирован, Rails выводит CSRF-токен в метатеге, а `POST /likes` возвращает JSON с полем `count`. Без CSRF-токена запрос к защищённому Rails-маршруту может быть отклонён. Обработка ошибки здесь только пишет в консоль; для реального интерфейса стоит показать её пользователю и при необходимости блокировать повторные нажатия на время запроса.

**Плюсы:**
- Логика вынесена из HTML, а связь с элементами явно задана атрибутами.
- Подходит для поведения, которому нужен доступ к DOM и жизненному циклу элементов.
- Может использоваться с importmap или со сборкой — в зависимости от проекта.

**Ограничения:**
- Нужны подключение библиотеки и регистрация контроллеров, хотя сборка не обязательна.
- Для одной простой операции отдельный контроллер может быть избыточен.

**Когда брать?**  
Когда поведения на странице становится достаточно много, чтобы организовать его в отдельные контроллеры, особенно в Rails-проекте с Hotwire.

## 💥 Антипаттерны

1. **Смешивать Alpine.js и Stimulus без необходимости**  
   Совместное использование допустимо, но если оба инструмента управляют одним и тем же состоянием или элементом, поведение сложнее отлаживать. Разделяйте их зоны ответственности.

2. **Использовать htmx для любого поведения**  
   htmx удобен для запросов и подстановки HTML. Для перетаскивания элементов и другой сложной локальной логики понадобится JavaScript — например, контроллер Stimulus.

3. **Размещать всю логику Alpine.js в атрибутах**  
   Если выражения в `x-data` и обработчиках трудно читать, вынесите их в `Alpine.data` или отдельный модуль. Само наличие массива или пагинации ещё не означает, что нужно менять библиотеку.

## 🧪 Тестирование

**Alpine.js:**  
Проверяйте интерактивность системными тестами с JS-драйвером, например через Capybara. Вынесенную логику можно тестировать отдельно.

**Stimulus:**  
Контроллеры можно тестировать с Jest или Vitest, но для проверки связи с `data-controller`, действиями и целями понадобится DOM-окружение или браузерный тест.

**htmx:**  
Проверяйте серверные маршруты и возвращаемый HTML, например в RSpec. То, что ответ вставляется в нужное место страницы, проверяйте системным тестом с JS-драйвером.

## 🎤 Что сказать на собеседовании

> — Почему вы не используете React/Vue?

— Наш проект в основном рендерит HTML на сервере, а для интерактивности нам хватает Stimulus. Turbo помогает обновлять страницы и фрагменты без отдельного SPA-фронтенда. Если требования к интерфейсу изменятся, пересмотрим выбор.

## 🏁 Вывод

**Выбирайте инструмент под задачу:**  
- Нужно локальное состояние для меню или аккордеона? **Alpine.js**.
- Нужно запросить и вставить HTML с сервера? **htmx**.
- Нужно организовать поведение элементов в контроллеры? **Stimulus**.

Они не обязаны заменять друг друга или использоваться вместе. Начните с того, какое поведение нужно странице и что уже умеет ваш Rails-проект.
