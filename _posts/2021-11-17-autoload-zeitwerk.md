Ruby не ищет файл с классом автоматически при каждом обращении к константе. Разберём, когда файл нужно загрузить явно, как работает отложенная загрузка и почему в Rails класс из `app/models` обычно доступен без `require`.

---

## 🧱 Как Ruby находит классы

Обычно ты пишешь:

```ruby
require 'json'
puts JSON.parse('{}')
```

`require` ищет подходящий файл в путях из `$LOAD_PATH` и загружает его один раз. Если нужен повторный запуск содержимого файла, есть `load`: он выполняет файл при каждом вызове. Для определения классов и загрузки зависимостей обычно нужен именно `require`.

---

## 🧨 `require` vs `require_relative`

* `require` ищет файл через `$LOAD_PATH`.
* `require_relative` разрешает путь относительно файла, из которого вызван, а не относительно текущей рабочей директории.

```ruby
require_relative '../lib/my_tool'
```

`require_relative` удобен для файлов проекта, расположение которых относительно друг друга известно. Он не опаснее `require` и не гарантирует ускорения: выбор зависит от того, должен ли путь определяться структурой проекта или путями загрузки.

---

## 🧪 `autoload`: отложенная загрузка

```ruby
autoload :Foo, 'foo'

# При первом обращении к Foo Ruby попытается загрузить foo.rb
Foo.new
```

`autoload` связывает константу с файлом. При первом обращении к `Foo` Ruby загрузит файл; для успешного обращения тот должен определить нужную константу. Механизм не устарел: Zeitwerk тоже использует Ruby `autoload`, но берёт на себя регистрацию констант по структуре файлов.

---

## 🧠 `const_missing` — обработка ненайденной константы

Ruby вызывает `const_missing`, если не смог разрешить константу. На нём можно построить собственную загрузку, но перехватывать все отсутствующие константы глобально рискованно. Вот ограниченный пример для одного пространства имён:

```ruby
module MyApp
  def self.const_missing(name)
    return super unless name == :User

    require_relative 'my_app/user'
    return const_get(name, false) if const_defined?(name, false)

    super
  end
end

# В my_app/user.rb определён MyApp::User
MyApp::User.new
```

Здесь путь задан для файла, расположенного рядом с директорией `my_app`. Если файл загрузится, но не определит `MyApp::User`, вызов перейдёт к обычной обработке отсутствующей константы и завершится `NameError`. Без проверки перед `const_get` обработчик мог бы снова вызвать `const_missing` и уйти в рекурсию. В Rails для такой задачи обычно не нужен собственный обработчик: загрузкой управляет Zeitwerk.

---

## 🚆 Zeitwerk: автозагрузчик в Rails

Начиная с Rails 6 Zeitwerk используется как загрузчик по умолчанию. Он сопоставляет пути файлов с именами констант и регистрирует их через Ruby `autoload`. Прежний классический загрузчик Rails опирался на `const_missing`.

```ruby
# app/models/user.rb
class User
end

# В коде приложения:
User.new # файл будет загружен при обращении к User
```

Это работает, если файл находится в пути автозагрузки, а его имя и определённая в нём константа согласованы.

---

## 🧹 Требования Zeitwerk

1. **Имя файла должно соответствовать имени константы.**

   ```ruby
   # app/models/super_bot.rb
   class SuperBot
   end
   ```

2. **Вложенные директории задают пространства имён.**

   ```ruby
   # app/models/admin/report.rb
   module Admin
     class Report
     end
   end
   ```

3. **Не загружай через `require` вручную файлы приложения, которыми управляет автозагрузчик.** Для внешних библиотек и файлов вне его путей `require` по-прежнему нужен.

---

## 📦 Как добавить свой путь в автозагрузку

Если классы в `lib/` должны загружаться по константе, путь можно добавить в конфигурации приложения:

```ruby
# config/application.rb, внутри класса Application < Rails::Application
config.autoload_paths << Rails.root.join('lib')
```

После этого файлы в `lib/` должны соответствовать соглашениям об именах Zeitwerk. Простого создания директории `lib/` недостаточно, чтобы считать всё её содержимое автозагружаемым. Не добавляй в путь автозагрузки файлы, которые не предназначены для загрузки как константы.

---

## 🧨 Вопрос с подвохом

```ruby
class App
  autoload :Config, 'config'
end

App::Config # Что произойдёт?
```

Ruby попытается загрузить `config.rb`. Обращение сработает, если файл определит именно `App::Config`. Если в нём определён только `Configuration`, обращение к `App::Config` завершится `NameError`.

---

## 🚨 Почему не стоит просто писать `require 'user'` в Rails?

Если `User` определён в `app/models/user.rb`, Zeitwerk уже управляет его загрузкой. Ручной `require` может загрузить файл в обход этого механизма: `require` запоминает загруженные файлы и не рассчитан на повторную загрузку изменённого кода при перезагрузке в режиме разработки. Кроме того, `require 'user'` ищет файл через `$LOAD_PATH` и не обязательно найдёт нужный файл приложения.

Обращайся к `User` как к константе. Для кода вне путей автозагрузки используй `require` либо явно добавь подходящий путь в конфигурацию автозагрузки.

---

**Вывод:** `require` загружает файл явно, `autoload` — при обращении к константе, а Zeitwerk связывает константы с файлами по соглашениям об именах. Если Ruby сообщает `uninitialized constant`, проверь не только наличие файла, но и путь загрузки, имя файла и константу, которую он определяет.
