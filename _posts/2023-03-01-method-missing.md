Метод `method_missing` в Ruby позволяет обрабатывать вызовы методов, которые объект не смог найти. Это бывает полезно для DSL, динамических API и прокси-объектов. Но если перехватывать любой вызов или забыть о `respond_to_missing?`, код начнёт скрывать ошибки и противоречить результатам `respond_to?`.

## 🤔 Что это такое?

Когда Ruby не может вызвать метод у объекта, он передаёт вызов в `method_missing`. Простейший пример:

```ruby
class Ghost
  def method_missing(name, *args)
    puts "Вызван несуществующий метод: #{name}, args: #{args.inspect}"
  end
end

g = Ghost.new
g.hello("world")  # вывод: Вызван несуществующий метод: hello, args: ["world"]
```

Такой вариант годится для демонстрации, но не для обработки конкретного семейства методов: он молча принимает и опечатки, а `respond_to?(:hello)` при этом вернёт `false`.

## ⚠️ Подводные камни

1. Если не ограничить набор обрабатываемых имён, `method_missing` скроет опечатки вместо того, чтобы сообщить об ошибке.
2. Если динамические методы не отражены в `respond_to_missing?`, объект сможет обработать вызов, но `respond_to?` сообщит, что метода нет.
3. Динамические методы сложнее обнаруживать автодополнению IDE и инструментам рефакторинга.

## ✅ Как правильно?

Обрабатывай только те имена, для которых действительно предусмотрено поведение. Остальные вызовы передавай в `super`. Если объект поддерживает динамические методы `ghost_*`, сообщи о них и через `respond_to_missing?`:

```ruby
class Ghost
  def method_missing(name, *args)
    return super unless name.to_s.start_with?("ghost_")

    puts "Вызван динамический метод: #{name}, args: #{args.inspect}"
  end

  def respond_to_missing?(name, include_private = false)
    name.to_s.start_with?("ghost_") || super
  end
end

g = Ghost.new
g.ghost_scare("world")        # вывод: Вызван динамический метод: ghost_scare, args: ["world"]
g.respond_to?(:ghost_scare)  # => true
g.respond_to?(:hello)        # => false
g.hello                      # => NoMethodError
```

Здесь проверка префикса одинакова в обоих методах. Но она не отличит задуманное имя от опечатки внутри `ghost_*`: например, `ghost_scrae` тоже будет принято. Если набор допустимых имён известен, проверяй именно его.

## 📌 Когда уместно использовать?

* Для DSL с заранее оговорённым правилом формирования имён методов.
* Для обёрток над API с действительно динамическими методами.
* Для прокси-объектов, которым нужно перенаправлять вызовы.

В каждом случае важно определить, какие вызовы объект поддерживает, и согласовать это правило с `respond_to_missing?`.

## 🙅 Когда не стоит?

* Когда метод можно определить явно без лишней сложности.
* Когда набор методов известен заранее: их можно создать через `define_method`.
* Когда нужна лишь передача вызова другому объекту: сначала рассмотрите явное делегирование. `send` и `public_send` вызывают методы, а не заменяют их определение или `method_missing`.

## 🤯 А можно перегрузить метод, если он уже есть?

Нет, через `method_missing` — нельзя: для найденного метода он не вызывается. Если нужно изменить поведение существующего метода, его придётся переопределить или обернуть другим способом.
