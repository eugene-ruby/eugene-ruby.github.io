Вы знаете этот момент, когда CI не может скачать гем, а дедлайн — вчера? Сборка зависит не только от вашего кода, но и от доступности источников зависимостей.

Разберём, как сохранить гемы в репозитории и устанавливать их локально. Это полезно, если CI или развёртывание должны работать без доступа к RubyGems. Для зависимостей из Git и других источников тоже есть нюансы.

---

## 🎲 Почему «просто bundle install» — это русская рулетка

Типичный сценарий:

```bash
bundle install
# ...
Gem::RemoteFetcher::FetchError: bad response Service Unavailable 503
```

**Что может помешать сборке:**

1. **Недоступный источник зависимостей.** Если нужного гема нет локально, Bundler может обратиться к внешнему сервису.
2. **Незапланированное обновление.** `bundle update` может изменить версии в `Gemfile.lock` в пределах ограничений из `Gemfile`. Обычный `bundle install` с зафиксированным lock-файлом не должен произвольно обновлять версии.
3. **Повторная загрузка.** На новом CI-агенте или в сборке без доступного кеша гемы придётся скачивать заново.

> «Но у нас же кеш!» — скажете вы.
> Он помогает, пока доступен именно в той среде, где идёт сборка.

## 🧰 Что такое vendoring гемов?

В этой статье **vendoring** — хранение пакетов зависимостей вместе с проектом. Помимо `Gemfile` и `Gemfile.lock` в репозитории появляется `vendor/cache`:

```text
Gemfile
Gemfile.lock
vendor/cache/ # пакеты гемов и кешируемые источники зависимостей
```

### Как это работает?

1. **Локальный кеш:** Bundler сохраняет пакеты для зависимостей из lock-файла в `vendor/cache`.
2. **Установка без обращения к источникам:** `bundle install --local` использует доступные локально пакеты и установленные гемы, не скачивая недостающие.
3. **Зафиксированные версии:** за выбор версий отвечает `Gemfile.lock`; кеш позволяет получить эти версии без загрузки из сети.

## 🔧 Практика: как завести vendoring в проекте

### Шаг 1. Инициализация

```bash
bundle package --all
```

Флаг `--all` нужен, чтобы кешировать также зависимости из Git и локальных источников (`path`). Он **не включает отключённые группы**: перед упаковкой проверьте настройки Bundler, в том числе `BUNDLE_WITHOUT`, и убедитесь, что в `Gemfile.lock` есть зависимости, нужные CI.

Для установки на другой платформе одного набора файлов в `vendor/cache` может быть недостаточно. Проверьте, что нужная платформа учтена в lock-файле и её пакеты доступны в кеше.

### Шаг 2. CI/CD без интернета

Добавляем в скрипт сборки или деплоя:

```bash
bundle install --local || exit 1
```

Если нужной зависимости нет ни в `vendor/cache`, ни среди уже установленных гемов, установка завершится ошибкой, а не начнёт скачивание. Поэтому успешный запуск на машине разработчика ещё не доказывает, что репозиторий содержит всё необходимое.

### Шаг 3. Обновление гемов

Когда нужно обновить зависимость:

```bash
bundle update some-gem
bundle package --all
git add Gemfile.lock vendor/cache
git commit -m "Update some-gem"
```

Обновление может потребовать сети; после него коммитьте lock-файл вместе с изменениями кеша.

## 💣 Антипаттерны

### 1. «Vendor’им только production-гемы»

Если CI запускает тесты или линтеры, ему нужны и их зависимости. Проверьте, что группы с `rspec`, `rubocop` и другими инструментами не исключены при подготовке кеша. Команда `bundle package --no-install` сама по себе **не означает** «упаковать только production-гемы»: она пропускает установку после упаковки.

### 2. «Добавим vendor/cache в .dockerignore»

Если Dockerfile копирует `vendor/cache` из контекста сборки, исключение этого каталога лишит образ локальных пакетов. Тогда `bundle install --local` может завершиться ошибкой; замена его обычным `bundle install` вернёт зависимость от сети.

### 3. «Зачем это, если есть Docker layer caching?»

Кеш слоёв ускоряет повторную сборку, но на новом сборщике нужного слоя может не быть. Vendoring решает другую задачу: делает пакеты доступными из репозитория.

## 🏗️ Интеграция с Rails и PostgreSQL

### Пример для Dockerfile

Фрагмент для образа, в котором уже есть Ruby и системные зависимости приложения:

```dockerfile
WORKDIR /app
COPY Gemfile Gemfile.lock ./
COPY vendor/cache ./vendor/cache
RUN bundle install --local
```

Здесь важно сохранить путь `vendor/cache` **внутри каталога проекта**. Копирование в `/vendor/cache` при рабочем каталоге `/app` не даст Bundler кеш по ожидаемому пути.

### Для проектов с нативными расширениями

Некоторые гемы, например `pg` для PostgreSQL, могут требовать системные библиотеки и инструменты сборки. Vendoring сохраняет пакет гема, но не заменяет эти зависимости в образе.

Если для вашей платформы нужен гем с исходниками Ruby вместо готового платформенного пакета, можно настроить Bundler:

```bash
bundle config set force_ruby_platform true
bundle package --all
```

Это **не превращает гем с нативным расширением в чистый Ruby-гем**: расширение всё равно может потребоваться скомпилировать при установке. Выбирайте настройку с учётом целевой платформы и доступных системных библиотек.

## 🧪 Тестируем vendoring

Проверяйте установку в чистой среде, где нет заранее установленных гемов и доступных внешних кешей. Для показанного Dockerfile можно запустить сборку без сети:

```bash
docker build --network=none .
```

Базовый образ при этом уже должен быть доступен локально, а другие шаги Dockerfile не должны требовать сеть. Если `bundle install --local` падает, проверьте отсутствующий пакет, платформу в `Gemfile.lock` и настройки исключённых групп. Удаление одного лишь `~/.bundle/cache` не даёт такой проверки: гемы могут оставаться установленными в других каталогах.

## 🎤 Что сказать на собеседовании

> — Как вы уменьшаете зависимость деплоя от внешних сервисов?

— Храним пакеты гемов рядом с проектом и устанавливаем зависимости через `bundle install --local`. Версии фиксирует `Gemfile.lock`. Для работы без сети проверяем сборку в чистой среде и отдельно готовим системные зависимости, если гемам нужны нативные расширения.

## 🧾 Вывод

**Vendoring — это как носить с собой аптечку вместо надежды на ближайшую больницу.** Он позволяет не скачивать гемы при каждой установке и помогает собирать проект без доступа к их источникам.

Цена — место в репозитории и необходимость обновлять `vendor/cache` вместе с `Gemfile.lock`. Перед тем как полагаться на кеш в CI, проверьте его на целевой платформе в чистой среде без сети.
