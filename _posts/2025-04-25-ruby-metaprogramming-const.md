Константы и переменные в Ruby можно читать и изменять по имени. Это полезно в метапрограммировании, но обход привычных методов доступа требует осторожности. Разберём примеры — от динамического создания классов до очистки состояния в тестах.

---

## 🔍 Введение: зачем это нужно?

Представьте: вы открываете старый проект, а там...
```ruby
class Magic
  KLASS = case ENV['MODE']
          when 'prod' then ProductionSpell
          when 'test' then TestSpell
          else DebugSpell
          end
end
```
Константа выбирается при загрузке класса. Если нужно подменить её в тесте, сначала стоит понять, когда загружается `Magic` и кто уже использует `Magic::KLASS`: замена константы не обновит ссылки, сохранённые ранее. Методы ниже помогают работать с такими случаями, но не делают подмену автоматически безопасной.

---

# 📌 Константы: динамический доступ

## `const_get` / `const_set` — читаем и пишем константы

`const_get` получает константу по имени, а `const_set` задаёт её. Имя можно передать строкой или символом.

**Пример:** динамическое создание классов для плагинов:
```ruby
module Plugins; end

%w[Search Export].each do |name|
  Plugins.const_set(name, Class.new(PluginBase))
end

search_plugin = Plugins.const_get('Search', false)
```
Здесь создаются классы `Plugins::Search` и `Plugins::Export`. Код не загружает файлы плагинов и не добавляет классам поведение: за это должна отвечать отдельная часть системы. Аргумент `false` в `const_get` ограничивает поиск константами самого модуля `Plugins`.

**Антипаттерн:** переопределять стандартные константы:
```ruby
# ❌ Обращения к String начнут получать другой класс
Object.const_set(:String, MyWeirdString)
```
Ruby предупредит о повторном определении константы. Уже созданные строки при этом не сменят класс, но код, который позднее обратится к `String`, может работать не так, как ожидалось.

---

## `const_defined?` — проверка на существование

Проверяет, доступна ли константа. Если важно узнать, определена ли она **непосредственно** в данном модуле или классе, передайте `false` вторым аргументом:
```ruby
module MyGem; end

unless MyGem.const_defined?(:Config, false)
  MyGem.const_set(:Config, Class.new)
end
```
Такая проверка не заменяет загрузку зависимости: не стоит пропускать `require 'redis'` только потому, что где-то уже определена константа `Redis`.

**Ловушка:** по умолчанию `const_defined?` ищет и среди предков:
```ruby
module A; MY_CONST = 1; end
class B; include A; end

B.const_defined?(:MY_CONST)        #=> true
B.const_defined?(:MY_CONST, false) #=> false
```

---

## `remove_const` — удаление констант

Удаляет константу, определённую непосредственно в модуле или классе. Метод приватный, поэтому при явном вызове обычно используют `send`.

**Пример:** очистка константы, созданной специально для теста:
```ruby
RSpec.describe MyGem do
  after do
    if MyGem.const_defined?(:TestConfig, false)
      MyGem.send(:remove_const, :TestConfig)
    end
  end
end
```
Такой приём подходит, только если тест владеет этой константой. Иначе очистка может удалить состояние, нужное другим тестам; если константу подменяли, после теста нужно восстановить прежнее значение.

**Важно:** удаление имени не уничтожает объект, на который указывала константа. Существующие экземпляры и другие ссылки на класс продолжат работать, пока на них есть ссылки. Повторное создание константы с тем же именем тоже не превратит старые экземпляры в экземпляры нового класса.

# 🏗️ Переменные экземпляра

## `instance_variable_get` / `instance_variable_set`

Читают и записывают переменную экземпляра по имени с `@`. Эти методы обходят обычные методы доступа и проверки, которые могли быть в них предусмотрены.

**Пример:** восстановление состояния из данных, которым вы доверяете:
```ruby
class User
  attr_reader :name, :age
end

json = { '@name' => 'John', '@age' => 30 }

user = User.new
json.each do |key, value|
  user.instance_variable_set(key, value)
end
```
Несмотря на имя `json`, здесь показан уже подготовленный хеш, а не разбор JSON-строки. Не передавайте ключи из внешних данных в `instance_variable_set` без ограничений: они могут изменить поля, которые вы не собирались заполнять. Для таких данных лучше использовать конструктор или явный список допустимых полей.

**Антипаттерн:** постоянно обращаться к переменным экземпляра этим способом вместо обычных методов доступа.

---

## `instance_variables` — список переменных

Возвращает массив имён переменных экземпляра в виде символов с `@`.

**Пример:** отладка состояния объекта:
```ruby
def debug(obj)
  puts "Variables: #{obj.instance_variables.join(', ')}"
end
```
Метод показывает имена, но не значения переменных.

---

# 🏛️ Переменные класса

## `class_variable_get` / `class_variable_set`

Читают и записывают переменные класса (`@@`) по имени. В отличие от переменных экземпляра класса, такие переменные могут быть общими для классов в одной иерархии.

**Пример:** кеш, общий для базового и дочернего классов:
```ruby
class Base
  @@cache = {}

  def self.add_to_cache(key, value)
    class_variable_get(:@@cache)[key] = value
  end

  def self.cache
    class_variable_get(:@@cache)
  end
end

class Child < Base; end

Child.add_to_cache(:answer, 42)
Base.cache #=> { answer: 42 }
```
Если каждому подклассу нужен отдельный кеш, `@@cache` здесь не подходит: запись через `Child` меняет состояние, видимое через `Base`.

---

## `class_variables` — список переменных класса

Возвращает массив имён переменных класса, доступных классу. По умолчанию в результат могут входить переменные предков.

**Пример:** сигнал для проверки использования переменных класса:
```ruby
if MyClass.class_variables.any?
  logger.warn "Class variables detected in #{MyClass}"
end
```
Такой сигнал сам по себе не означает ошибку: сначала проверьте, где определены переменные и должно ли их состояние быть общим.

---

## 🎯 Вывод: когда это реально нужно?

1. **Метапрограммирование:** создавать классы и находить константы по имени.
2. **Тесты:** управлять константами, созданными для теста, и восстанавливать подменённое состояние.
3. **Инструменты:** исследовать состояние объектов и реализовывать сериализацию с явными ограничениями.
4. **Legacy-код:** работать с существующими соглашениями, которые нельзя быстро изменить.

Если задачу можно решить обычными методами, начните с них. Динамический доступ полезен, когда имя известно только во время выполнения, но требует внимания к области поиска и общему состоянию.

```ruby
# Для доступа к константе по имени не нужен eval:
MyClass.const_get(:Settings, false)
```
