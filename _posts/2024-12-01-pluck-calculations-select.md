В Rails `pluck`, методы расчёта (`count`, `sum`, `average`) и `select` помогают получать из PostgreSQL только нужные данные. Но результат у них разный: где-то ты получишь массив значений, а где-то — модель, у которой загружена лишь часть атрибутов.

---

Когда тебе не нужны полноценные модели, эти методы могут сэкономить ресурсы. Важно учитывать и их ограничения.

## 🍇 pluck

```ruby
User.where(active: true).pluck(:email)
# => ["user1@example.com", "user2@example.com", ...]
```

Возвращает **массив значений**, не создавая объекты `User`. Если передать несколько столбцов, получится массив массивов.

⚠️ Если ID нужны только для следующего запроса, не обязательно сначала загружать их через `pluck(:id)`: большой список займёт память приложения и попадёт в следующий SQL-запрос как набор значений. Вместо этого можно передать подзапрос:

```ruby
Post.where(user_id: User.where(active: true).select(:id))
```

Для небольшого списка, который нужен именно в Ruby, `pluck(:id)` остаётся уместным.

## 🧮 calculations

```ruby
User.count
User.sum(:age)
User.average(:salary)
```

Агрегаты вычисляются в базе, без загрузки всех подходящих моделей в Ruby. Но скорость зависит от запроса, объёма данных и условий фильтрации — сама по себе замена загрузки записей на `count` или `sum` не гарантирует быстрый ответ.

> `average` не стоит считать методом, который всегда возвращает `Float`: тип результата зависит в том числе от типа столбца и приведения значения ActiveRecord.

---

## 🧠 select с алиасами

```ruby
User.select("users.id, COUNT(posts.id) AS posts_count")
    .joins(:posts)
    .group("users.id")
```

У полученного объекта можно прочитать `user.posts_count`, потому что алиас включён в `SELECT`. При этом `joins(:posts)` вернёт только пользователей, у которых есть записи в `posts`. Если нужны и пользователи без записей, потребуется `left_joins(:posts)`.

Алиас доступен у объектов, полученных этим запросом. Если заново загрузить `User` обычным запросом, `posts_count` в результате уже не будет.

---

## 😵 Частичный select: незагруженные атрибуты

```ruby
user = User.select(:id).first
user.name # => ActiveModel::MissingAttributeError, если пользователь найден
```

`select(:id)` создаёт объект `User`, но не загружает `name`. Обращение к незагруженному атрибуту вызывает ошибку, а не возвращает `nil`. Выбирай все поля, которые понадобятся у модели; если нужны только отдельные значения, используй `pluck`.

## 📌 Сравнение

| Метод | Возвращает | Когда использовать |
| --- | --- | --- |
| `pluck(:email)` | массив значений | Нужны значения без объектов модели |
| `count`, `sum` | числовой результат агрегата | Нужен подсчёт или сумма по запросу |
| `select(...)` с алиасом | объекты с выбранными атрибутами и алиасом | Нужны модели с вычисленным полем |
| `select(...)` без нужного атрибута | объекты без этого атрибута | Учитывай, что обращение к нему вызовет ошибку |
