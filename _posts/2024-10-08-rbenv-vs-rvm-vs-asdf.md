Вы только что установили свежую Ubuntu, открыли терминал с планами на новый Rails-проект — и видите `ruby: command not found`. Или Ruby есть, но проекту нужна другая версия. Разберём три менеджера версий — **RVM**, **rbenv** и **chruby** — и посмотрим, где каждый из них удобен, а где потребует дополнительной настройки.

---

## 🧐 Зачем вообще эти менеджеры?

Потому что:

1. **Проекты могут использовать разные версии Ruby.** Переключаться между ними вручную неудобно.
2. **Системный Ruby лучше не менять ради проекта.** Установка гемов через `sudo gem install` может затронуть окружение, от которого зависят системные инструменты.
3. **Зависимости проектов нужно держать под контролем.** Bundler выбирает и фиксирует зависимости по `Gemfile` и `Gemfile.lock`. Gemset’ы решают другую задачу — разделяют установленные гемы между окружениями.

При выборе менеджера важно понять, как он переключает версии, что добавляет в настройку shell и нужна ли вам отдельная изоляция установленных гемов.

---

## 🧰 RVM: «Я — король!»

**RVM (Ruby Version Manager)** управляет версиями Ruby и gemset’ами. Возможностей много, но и вмешательство в окружение заметнее, чем у двух других вариантов.

```bash
# Установка: команда загружает и выполняет удалённый скрипт.
# Перед запуском стоит ознакомиться с инструкцией и скриптом установки.
\curl -sSL https://get.rvm.io | bash -s stable
```

### 👍 Плюсы:
- **Встроенные gemset’ы:** `rvm use 3.1.0@myapp --create` выбирает Ruby и создаёт gemset при необходимости.
- **Запуск команды в выбранном окружении:** например, `rvm 3.1.0@myapp do bundle install`.
- **Документация и возможности настройки.**

### 👎 Минусы:
- **Интегрируется с shell:** использует функции и настройки инициализации, что может осложнять разбор проблем с окружением.
- **Дополнительная обвязка при запуске shell:** насколько она заметна, зависит от конфигурации.
- **Больше настроек:** бывает сложнее понять, откуда взялась текущая версия Ruby или gemset.

### 💀 Частая путаница:
```bash
# Переключает Ruby в текущем shell, но не задаёт версию по умолчанию
rvm use 3.0.0
```

Если версия нужна только одному проекту, не стоит полагаться на ручное переключение: при открытии нового терминала окружение может быть другим. Версию проекта лучше зафиксировать в файле конфигурации и проверить, как RVM его обрабатывает.

## 🧊 rbenv: «Минимализм — наше всё»

**rbenv** выбирает версию Ruby с помощью shims — исполняемых файлов в `PATH`, которые передают вызов нужной установленной версии. Для установки самих версий обычно используют `ruby-build`.

```bash
# Установка через Homebrew (macOS)
brew install rbenv ruby-build
```

После установки нужно настроить инициализацию rbenv для своего shell, чтобы shims оказались в `PATH`. Команда с Homebrew выше не подходит для Ubuntu из вступления.

### 👍 Плюсы:
- **Небольшая интеграция с shell:** выбор версии не требует переключать окружение командой при каждом переходе в проект.
- **Предсказуемый выбор версии:** `rbenv local` записывает версию в `.ruby-version`; rbenv также учитывает версии, заданные для shell и по умолчанию.
- **Плагины:** например, `rbenv-vars` для переменных окружения.

### 👎 Минусы:
- **Нет встроенных gemset’ов.** Bundler управляет зависимостями, но не является заменой gemset’ов для изоляции установленных гемов.
- **Для установки Ruby нужен отдельный инструмент,** например `ruby-build`; сборка может потребовать системных зависимостей.

### 🎯 Пример для проекта:
```bash
# Устанавливаем Ruby с помощью ruby-build
rbenv install 3.2.2

# Записываем версию в .ruby-version проекта
cd my_project
rbenv local 3.2.2

# Проверяем, какая версия выбрана
rbenv version
```

При корректно настроенных shims rbenv будет выбирать версию по `.ruby-version` при запуске команд Ruby из каталога проекта.

---

## ⚡ chruby: «Я просто переключаю Ruby»

**chruby** переключает Ruby, изменяя переменные окружения текущего shell. Для установки версий Ruby можно использовать отдельный инструмент, например `ruby-install`.

```bash
# Установка через Homebrew (macOS)
brew install chruby ruby-install
```

Для работы команды `chruby` нужно подключить её скрипт в настройках shell.

### 👍 Плюсы:
- **Небольшая обвязка:** переключение устроено просто.
- **Прозрачность:** можно посмотреть, какие переменные окружения изменились.
- **Разделение задач:** chruby переключает версии, а установкой Ruby занимается другой инструмент.

### 👎 Минусы:
- **Автопереключение требует настройки:** для чтения `.ruby-version` нужно дополнительно подключить `auto.sh`.
- **Нет встроенных gemset’ов:** зависимости можно вести через Bundler, но это не то же самое, что отдельные наборы установленных гемов.

### 🔥 Для фанатов контроля:
```bash
# Вручную переключаемся на установленную версию
chruby 3.1.0

# Записываем версию для проекта
printf '3.1.0\n' > .ruby-version
```

Последняя команда только создаёт файл. Чтобы версия выбиралась при переходе в каталог, настройте `auto.sh` для своего shell.

## 🧪 Сравнение в бою

| Критерий | RVM | rbenv | chruby |
|---|---|---|---|
| Переключение версий | Командой и через конфигурацию проекта | Через shims и `.ruby-version` | Командой; по `.ruby-version` с `auto.sh` |
| Gemset’ы | Встроенные | Не встроены | Не встроены |
| Интеграция с shell | Функции и инициализация RVM | Инициализация и shims в `PATH` | Подключение скрипта; для автопереключения — `auto.sh` |
| Установка Ruby | Возможности RVM | Обычно `ruby-build` | Отдельный инструмент, например `ruby-install` |

Скорость и удобство отладки зависят от настройки окружения: без измерений и конкретного сценария расставлять менеджеры по местам было бы нечестно.

---

## 💡 Какой выбрать?

- **Если нужны встроенные gemset’ы:** присмотритесь к `RVM`, учитывая его интеграцию с shell.
- **Если достаточно выбора версии через `.ruby-version`:** `rbenv` вместе с `ruby-build` — вариант с небольшим числом встроенных возможностей.
- **Если хотите переключать уже установленные версии через окружение shell:** подойдёт `chruby`; автопереключение настраивается отдельно.

Лично мой стек:
```text
# На работе, где много legacy-проектов
RVM с конфигурацией проекта

# На личном MacBook
chruby + ruby-install + direnv

# На серверах
rbenv
```

С `.rvmrc` стоит быть осторожным: это исполняемый shell-код, поэтому не следует подтверждать его выполнение для непроверенного проекта. Если нужны только версия Ruby и имя gemset’а, можно рассмотреть `.ruby-version` и `.ruby-gemset`.

## 💥 Главная боль всех менеджеров

**Docker.** Если образу нужна одна версия Ruby, менеджер версий внутри него обычно избыточен: базовый образ уже задаёт Ruby.

```dockerfile
FROM ruby:3.2.2-alpine
WORKDIR /app
COPY Gemfile* ./
RUN bundle install
```

Это лишь фрагмент Dockerfile: для конкретного проекта могут понадобиться системные зависимости, исходный код приложения и остальные шаги сборки. Локально менеджер полезен, когда вы работаете с несколькими проектами или версиями Ruby; если версия одна, он не обязателен.

---

## 🎤 Что сказать на собеседовании

> — Как вы управляете версиями Ruby в проекте?

— Для локальной разработки используем `rbenv` с `ruby-build` и фиксируем версию проекта в `.ruby-version`. В Dockerfile выбираем базовый образ с нужной версией Ruby. Зависимости фиксируем через Bundler и `Gemfile.lock`; gemset’ы в этом сценарии нам не нужны.

---

## 🧾 Вывод

Выбирайте по задаче, а не по обещаниям скорости: **RVM** предлагает встроенные gemset’ы, **rbenv** — выбор версии через shims и `.ruby-version`, **chruby** — переключение установленного Ruby через окружение shell. Во всех случаях отдельно проверьте, как настроено ваше окружение и чем управляются зависимости проекта.
