Иногда нужно получить ID записей в Ruby, а иногда — только использовать их для фильтрации другого запроса. В ActiveRecord для этих задач подходят разные методы: `pluck(:id)`, `select(:id)` и `ids`. Разберём, почему выбор важен при большой выборке.

---

## 🧨 Почему это плохо:

```ruby
Post.where(user_id: User.active.pluck(:id))
```

Если активных пользователей — **100\_000**, `pluck(:id)` сначала выполнит запрос и загрузит все ID в массив Ruby. Затем ActiveRecord использует этот массив для условия `WHERE ... IN (...)` второго запроса.

🔎 Упрощённая схема SQL:

```sql
SELECT "id" FROM "users" WHERE "active" = TRUE;
-- А потом:
SELECT * FROM "posts" WHERE "user_id" IN (1, 2, 3, ..., 100000);
```

В реальном запросе вместо показанных чисел могут использоваться параметры. Проблема не в конкретном виде SQL: большой список ID нужно передать из базы в приложение, сохранить в памяти Ruby и передать обратно для второго запроса. Большое условие `IN` также может увеличить затраты на обработку запроса в PostgreSQL.

## ✅ Как лучше:

```ruby
Post.where(user_id: User.active.select(:id))
```

🔎 Упрощённая схема SQL:

```sql
SELECT * FROM "posts" WHERE "user_id" IN (
  SELECT "id" FROM "users" WHERE "active" = TRUE
);
```

Здесь `select(:id)` задаёт выборку ID как часть `ActiveRecord::Relation`. При выполнении запроса ActiveRecord использует её как подзапрос: промежуточный массив ID в Ruby не создаётся. Это полезно, когда ID нужны только для фильтрации записей. Сам запрос при этом не становится бесплатным: нагрузка на базу зависит в том числе от объёма данных и плана выполнения.

Если выполнить `User.active.select(:id)` отдельно и перебрать результат в Ruby, будут созданы объекты `User`, у которых выбрано только поле `id`. Для получения массива значений в Ruby лучше подходит `pluck(:id)`.

## 📦 А .ids?

```ruby
User.active.ids
```

`ids` возвращает массив первичных ключей, обычно без создания объектов моделей, если выборка ещё не загружена. Для этой задачи результат похож на `pluck(:id)`, но не стоит считать `ids` универсально более быстрым: поведение зависит, в частности, от того, загружена ли выборка.

> Если ID нужны для условия `where` и их может быть много, замена `pluck(:id)` на `ids` не решит проблему промежуточного массива. Используй подзапрос через `select(:id)`.

## 📌 Резюме

| Метод | Что возвращает | Когда уместен |
| --- | --- | --- |
| `pluck(:id)` | Массив ID в Ruby | Когда значения нужны в приложении |
| `select(:id)` | `ActiveRecord::Relation` с выборкой поля `id` | Когда ID можно использовать в SQL-подзапросе |
| `ids` | Массив первичных ключей в Ruby | Когда ключи нужны в приложении |

Главный вопрос: **нужен ли массив ID в Ruby?** Если он используется только для фильтрации другого запроса, подзапрос позволит не передавать весь список через приложение.
