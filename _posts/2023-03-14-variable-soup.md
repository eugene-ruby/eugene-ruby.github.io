Если ты когда-то на собеседовании перепутал `@`, `@@` и `$`, знай: ты не один. У этих префиксов разный смысл, а ошибка с `@@` особенно легко проявляется при наследовании. Разберём их на примерах.

---

## 🥸 Переменные в Ruby — в лицах

| Вид переменной | Синтаксис | Где хранится или определяется | Как доступна |
|----------------|-----------|-------------------------------|--------------|
| Локальная | `x` | В локальной области видимости | В ней же; блок может обращаться к переменным из окружающей области |
| Экземпляра | `@x` | В конкретном объекте | В коде, работающем с этим объектом; снаружи — через методы |
| Класса | `@@x` | В иерархии классов | Может совместно использоваться классом и его наследниками |
| Глобальная | `$x` | В состоянии программы | Из разных частей программы |
| Константа | `X` | В классе, модуле или на верхнем уровне | По правилам поиска констант, в том числе через `::` |

Класс в Ruby тоже объект. Поэтому `@x`, записанная в теле класса, принадлежит объекту-классу, а не его экземплярам.

---

## 🧪 Примеры в бою

```ruby
class Spaceship
  @@fleet_size = 0   # переменная класса

  def initialize(name)
    @name = name      # переменная экземпляра
    @@fleet_size += 1
  end

  def self.fleet_size
    @@fleet_size
  end

  def name
    @name
  end
end

s1 = Spaceship.new("Apollo")
s2 = Spaceship.new("Falcon")

puts s1.name              # => Apollo
puts Spaceship.fleet_size # => 2
```

У каждого корабля своё `@name`, а счётчик `@@fleet_size` общий. Если у `Spaceship` появятся наследники, их экземпляры тоже могут менять этот счётчик — это стоит учитывать.

---

## 🧬 Чем отличается `@` от `@@`?

```ruby
class Parent
  @@var = "from parent"
  @var  = "instance var of Parent"

  def self.vars
    [@@var, @var]
  end
end

class Child < Parent
  @@var = "from child"
  @var  = "instance var of Child"
end

puts Parent.vars.inspect # => ["from child", "instance var of Parent"]
puts Child.vars.inspect  # => ["from child", "instance var of Child"]
```

Здесь присваивание `@@var` в `Child` меняет переменную, доступную и через `Parent`. А `@var` принадлежит самому объекту-классу: у `Parent` и `Child` это две независимые переменные. Метод `vars` наследуется, но при вызове через `Child` его `@var` читается у `Child`.

---

## 💀 Зачем избегать @@?

В иерархии классов изменение `@@` в одном месте может повлиять на код, работающий с другим классом. Из-за этого труднее понять, кто поменял значение. Если нужно отдельное состояние для каждого класса, переменная класса здесь не подходит.

В таком случае можно хранить значение в переменной экземпляра *объекта-класса* и обращаться к нему через методы класса:

```ruby
class MyClass
  class << self
    attr_accessor :my_var
  end
end
```

Наследники унаследуют методы доступа, но значение `@my_var` у каждого класса будет своим. Это не прямая замена `@@`: если нужен именно общий счётчик для всей иерархии, отдельные переменные дадут другое поведение.

## 🗺 А что с \$переменными?

```ruby
$x = 42

class Demo
  def show
    puts $x
  end
end

Demo.new.show  # => 42
```

`$x` доступна из разных частей программы, поэтому менять её легко, а отследить источник изменения — сложнее. Для нового состояния приложения обычно лучше передавать зависимость явно или хранить её в подходящем объекте. При этом сами глобальные переменные не «бессмысленны»: в Ruby есть и встроенные глобальные переменные.

---

## 📌 Мнемоника:

* `@` — значение у конкретного объекта, в том числе у объекта-класса.
* `@@` — значение, которое может разделяться в иерархии классов.
* `$` — глобальная переменная, доступная из разных частей программы.

---

## ❗ Популярный подвох:

```ruby
class A
  def self.set
    @@x = 1
  end
end

class B < A
end

B.set
puts A.class_variable_get(:@@x) # => 1
```

`B` наследует метод `set`, определённый в `A`. Хотя вызов записан как `B.set`, присваивание `@@x` выполняется в методе, определённом в `A`, и значение доступно через `A`. При разборе похожей ошибки проверяй не только класс, через который вызвали метод, но и место, где метод определён.

---

🔚 **Вывод:** `@`, `@@` и `$` различаются не только записью, но и тем, кто разделяет их значение. Для состояния отдельного объекта используй `@`; прежде чем выбирать `@@` или `$`, проверь, действительно ли значение должно быть общим.
