Docker Hub — место, где можно хранить образы контейнеров и делиться ими. Разберём, как опубликовать образ pet-проекта, скачать его на другой машине, разобраться с тегами и не запутаться в ограничениях бесплатного плана.

---

## 🐶 Зачем вообще Docker Hub?

Представьте: вы написали микросервис для генерации мемов с котиками. Хотите:
- **Поделиться** образом с другом: «Вот мой `username/meow-api:1.0`!».
- **Развернуть** приложение на сервере, скачав туда готовый образ.
- **Автоматизировать** публикацию образа через GitHub Actions.

Docker Hub нужен не всегда: образ можно передать и другим способом. Но с реестром удобнее хранить его и получать на разных машинах.

---

## 📦 Основные команды: «Поводок и ошейник»

### 1. Логинимся
```bash
docker login
```
Для публикации нужен аккаунт Docker Hub и право на запись в репозиторий.

### 2. Собираем и пушим образ
```bash
docker build -t username/meow-api:1.0 .
docker push username/meow-api:1.0
```
Замените `username` на свой Docker Hub username. Имя с тегом при сборке и публикации должно совпадать: `docker push` отправляет уже собранный локальный образ, а не собирает его заново.

### 3. Забираем образ
```bash
docker pull username/meow-api:1.0
```
Так можно скачать образ на другой машине или обновить локальную копию, если образ с этим тегом перепубликовали.

---

## 🏷️ Теги: «Именные жетоны»

Тег — имя, по которому находят образ в репозитории. Оно может обозначать релиз или коммит, но само по себе не гарантирует неизменность образа: один и тот же тег можно опубликовать повторно.

| Тег | Когда использовать | Что учитывать |
|-----|--------------------|---------------|
| `:latest` | Для демо или тестов | Не означает автоматически «самую новую версию»: это обычный тег, который нужно публиковать отдельно |
| `:1.0` | Для обозначения релиза | Повторная публикация может изменить образ под тем же тегом |
| `:commit-a1b2` | Для привязки к конкретному коммиту | Тег полезен, если в процессе публикации его не перезаписывают другим образом |

**Антипаттерн:** пушить `:test1`, `:test2` и десятки похожих тегов без понятного назначения. Потом трудно определить, какой образ нужен. Если важна неизменность при развёртывании, можно использовать digest образа вместо тега.

---

## 🆓 Free-лимиты: «Бесплатный сыр»

На Docker Hub можно размещать публичные образы; приватные репозитории тоже доступны на бесплатном плане, но условия и квоты зависят от действующих правил сервиса. Перед публикацией проверьте настройки видимости репозитория и актуальные ограничения своего плана.

Для скачивания действуют ограничения на запросы: они зависят от того, выполняется ли pull анонимно или от имени пользователя, а также от условий плана. Дело не в том, сколько раз за месяц скачали именно ваш `meow-api`: лимит может затронуть клиента, который часто скачивает разные образы. Если упираетесь в ограничение анонимных запросов, авторизуйтесь там, где выполняется pull:
```bash
docker login
```
Это не отменяет все лимиты. Если условия Docker Hub не подходят, можно рассмотреть другой реестр, например GitHub Container Registry (GHCR), предварительно проверив его правила доступа и ограничения.

Не стоит рассчитывать и на правило «образ удалят через шесть месяцев без push»: универсального срока хранения из этого утверждения не следует.

## 🛠️ Практика: автоматизируем «выгул»

### 1. Собираем и пушим через GitHub Actions

Создайте репозиторий `meow-api` в Docker Hub и добавьте в секреты GitHub-репозитория `DOCKERHUB_USERNAME` и `DOCKERHUB_TOKEN`. Токену нужны права на публикацию образа.

```yaml
# .github/workflows/docker.yml
name: Publish image

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
      - run: |
          docker build -t "${{ secrets.DOCKERHUB_USERNAME }}/meow-api:$GITHUB_SHA" .
          docker push "${{ secrets.DOCKERHUB_USERNAME }}/meow-api:$GITHUB_SHA"
```

Workflow публикует образ для коммита, попавшего в `main`. Если ваша основная ветка называется иначе, замените `main`.

> ⚠️ **Если `docker build` идёт долго, а финальный образ получается большим**, проверьте Dockerfile:
>
> - Разместите шаги, которые редко меняются, до копирования часто изменяемого кода. Это поможет использовать кэш сборки, когда он доступен в вашей среде CI.
> - Используйте многостадийную сборку, если инструменты сборки не нужны приложению при запуске.
> - Отдельный базовый образ с зависимостями может быть полезен, если им пользуются несколько сборок, но его придётся обновлять и хранить.

Собирать образ вручную вместо CI — не универсальное решение: так сложнее воспроизводить публикацию. Подробнее о размере образа и сборке — в статье [«Docker-образы как чемоданы: как собрать быстро и не тащить лишнее»](/posts/slow-fat-docker-image.html).

### 2. Добавляем тег при релизе

Если образ для нужного коммита уже опубликован workflow, скачайте его и присвойте ему релизный тег. Выполняйте команды из рабочей копии нужного коммита, подставив свой username:

```bash
SHA=$(git rev-parse HEAD)
docker pull "username/meow-api:$SHA"
docker tag "username/meow-api:$SHA" username/meow-api:1.1
docker push username/meow-api:1.1
```

Перепубликация `:1.1` под другим образом изменит то, что получат пользователи этого тега.

### 3. Чистим локальные образы
```bash
docker image prune  # удалит образы без тегов, не используемые контейнерами
```

Команда очищает локальное хранилище Docker, а не репозиторий на Docker Hub.

## 💥 Неочевидные моменты

1. **«У меня нет прав!»**  
   Проверьте, что репозиторий создан в нужном аккаунте или организации, вы вошли под подходящей учётной записью и у неё есть право публиковать образы.

2. **«Почему pull такой медленный?»**  
   Проверьте соединение, размер скачиваемых слоёв и сообщения Docker. Если pull отклонён из-за лимита запросов, это не проблема скорости сети: проверьте авторизацию и условия вашего плана.

3. **«Мой образ исчез!»**  
   Проверьте имя репозитория и тег, видимость и права доступа, а также не удалили ли образ вручную. Не ориентируйтесь на срок с последнего push как на универсальное объяснение.

## 🎯 Вывод

Docker Hub помогает обмениваться образами приложений, публиковать их из CI и находить нужную сборку по тегу. Перед публикацией проверьте права на репозиторий, для развёртывания выбирайте тег или digest с учётом требований к воспроизводимости, а ограничения бесплатного плана сверяйте с действующими условиями сервиса. Теперь ваш pet-проект готов к прогулке! 🐕
