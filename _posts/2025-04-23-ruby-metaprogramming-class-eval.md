Методы `class_eval`, `instance_eval` и семейства `*_exec` позволяют выполнять код в контексте класса, модуля или объекта. Разберём, чем они отличаются, где полезны и почему особенно осторожно нужно обращаться со строками из внешних источников.

---
Вы когда-нибудь видели код, который «сам себя пишет»? В Ruby динамическое добавление методов возможно благодаря метапрограммированию — в том числе методам семейств `eval` и `exec`.

---

## 🧠 Теория: зачем это нужно?

Иногда методы нужно определять во время выполнения программы. Например:
- Добавить методы по конфигурации из заранее известных реализаций.
- Настроить поведение отдельного объекта.
- Создать DSL (Domain-Specific Language).

Во многих случаях хватит обычного определения методов, модуля или `define_method`. Методы ниже нужны, когда важно ещё и выбрать контекст выполнения кода.

---

## 🔧 Основные различия

| Метод | Контекст выполнения | Что принимает | Аргументы для блока |
|-------|---------------------|---------------|---------------------|
| `class_eval` | Класс или модуль | Блок или строку | Нет |
| `module_eval` | Класс или модуль | Блок или строку | Нет |
| `instance_eval` | Конкретный объект | Блок или строку | Нет |
| `class_exec` | Класс или модуль | Только блок | Да |
| `module_exec` | Класс или модуль | Только блок | Да |
| `instance_exec` | Конкретный объект | Только блок | Да |

`module_eval` — другое имя для `class_eval`, а `module_exec` — для `class_exec`. Здесь `*_exec` выполняют блок с переданными аргументами; не путайте их с `Kernel.exec`, который запускает другую программу вместо текущего процесса.

---

## 1️⃣ class_eval / module_eval (это одно и то же!)

**Что делает:** выполняет блок или строку в контексте класса либо модуля. В блоке `self` становится этим классом или модулем; определённый здесь через `def` метод становится методом его экземпляров.

```ruby
class User; end

User.class_eval do
  def say_hello
    "Hello from class_eval!"
  end
end

User.new.say_hello # => "Hello from class_eval!"
```

**Жизненный пример:** Добавление методов по YAML-конфигу. Конфиг выбирает только заранее предусмотренное поведение, а не содержит Ruby-код:

```ruby
# config/methods.yml
# methods:
#   admin:
#     - ban_user

require 'yaml'

class Admin
  attr_accessor :banned
end

allowed_methods = {
  'ban_user' => -> { self.banned = true }
}

methods_config = YAML.safe_load(File.read('config/methods.yml'))
Admin.class_eval do
  methods_config.fetch('methods').fetch('admin').each do |name|
    define_method(name, &allowed_methods.fetch(name))
  end
end
```

`fetch` отклонит неизвестное имя метода вместо того, чтобы выполнить содержимое конфига как Ruby-код. Если набор методов не зависит от конфига, проще определить их обычным способом; для повторного использования поведения между классами подойдёт `include` модуля.

## 2️⃣ instance_eval

**Что делает:** выполняет блок с `self`, равным конкретному объекту. Метод, определённый через `def` в таком блоке, становится методом только этого объекта.

```ruby
user = User.new
user.instance_eval do
  def personal_method
    "Only for this instance!"
  end
end

user.personal_method     # => "Only for this instance!"
User.new.personal_method # NoMethodError
```

**Жизненный пример:** Создание тестового объекта с уникальным поведением.

```ruby
test_user = User.new
test_user.instance_eval do
  def admin?
    true # В этом тесте пользователь считается администратором
  end
end
```

Такой приём уместен для отдельного объекта, но при частом использовании усложняет поиск места, где определён метод.

---

## 3️⃣ class_exec / module_exec

**Что делает:** как `class_eval` с блоком, но позволяет явно передать блоку аргументы.

```ruby
module Logging
  def self.add_logging(method_name)
    class_exec(method_name) do |name|
      define_method(name) do |*args|
        puts "Calling #{name} with #{args}"
        super(*args)
      end
    end
  end
end

class Calculator
  prepend Logging

  def add(a, b)
    a + b
  end
end

Logging.add_logging(:add)
Calculator.new.add(2, 3) # выводит "Calling add with [2, 3]"
                         # возвращает 5
```

**Жизненный пример:** Добавление логирования перед вызовом исходного метода. Здесь `prepend` помещает `Logging` перед `Calculator` в цепочке поиска методов, поэтому `super` вызывает `Calculator#add`. Метод добавляется в общий модуль `Logging`: если его подключают к другим классам через `prepend`, изменение затронет и их. Для логирования только одного класса нужен отдельный модуль-обёртка.

## 4️⃣ instance_exec

**Что делает:** как `instance_eval` с блоком, но позволяет передать блоку аргументы. Это удобно, когда колбэку нужны и данные, и доступ к объекту через `self`.

```ruby
class Button
  def initialize
    @state = 'off'
  end

  def update_state(new_state, &callback)
    @state = new_state
    instance_exec(new_state, &callback) if callback
  end

  def state
    @state
  end
end

button = Button.new
button.update_state('on') do |state|
  puts "#{self.class}: #{state}" # выводит "Button: on"
end
puts button.state # выводит "on"
```

**Практическое применение:** Колбэки в API, где блоку нужен доступ к состоянию принимающего объекта. Но из-за смены `self` такой API может удивить вызывающий код — её стоит явно описывать.

## 💣 Опасности и подводные камни

1. **Безопасность:** Не выполняйте пользовательский ввод как Ruby-код:
   ```ruby
   # ОПАСНО: строка выполняется как Ruby-код
   User.class_eval(params[:code])
   ```
   Злоумышленник сможет передать не только определение метода, но и произвольные команды. Не помогает и подстановка строк из внешнего конфига в исходный код метода. Вместо этого разбирайте данные и выбирайте поведение из заранее разрешённого набора, как в примере с YAML.

2. **Производительность:** При выполнении строки Ruby разбирает её как код; массовое создание методов во время работы тоже имеет стоимость. Это не означает, что каждый последующий вызов такого метода обязательно медленнее вызова метода, объявленного заранее. Если скорость важна, измеряйте свой сценарий.

3. **Отладка:** Происхождение динамически созданных методов может быть сложнее найти. Держите их определение рядом с кодом, который выбирает имена и поведение, и не используйте метапрограммирование там, где достаточно обычного метода.

## 🧾 Вывод

`class_eval` и `instance_eval` меняют контекст выполнения блока или строки, а методы `*_exec` позволяют дополнительно передать блоку аргументы. Они полезны, когда поведение действительно нужно создавать динамически. Если же задача решается обычным методом или модулем, такой код обычно проще поддерживать.
