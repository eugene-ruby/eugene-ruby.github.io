Итераторы в Ruby выходят далеко за рамки простого `each`. Разберём, чем отличаются `Enumerator`, `Enumerator::Lazy` и `Fiber`, как получать значения по одному и когда это помогает не обрабатывать данные заранее.

---

## 🪜 Что такое Enumerator?

```ruby
enum = [1, 2, 3].each
puts enum.class # => Enumerator

enum.each { |x| puts x }
```

Вызов `each` без блока возвращает `Enumerator`: обход ещё не выполнен. Его можно сохранить, передать другому методу или получать значения вручную через `next`. Но обычный `Enumerator` сам по себе не делает цепочки `map` и `select` ленивыми — для этого нужен `lazy`.

---

## 🧃 `Enumerator::Lazy`

```ruby
lazy = (1..Float::INFINITY).lazy
        .select(&:even?)
        .map { |x| x * 10 }

p lazy.first(5) # => [20, 40, 60, 80, 100]
```

`select` и `map` в этой цепочке обрабатывают элементы только тогда, когда `first(5)` запрашивает результат. Без `.lazy` обычный `select` попытался бы пройти бесконечный диапазон целиком и не дошёл бы до `map`.

---

## 🧵 Fiber — ниточка управления

```ruby
f = Fiber.new do
  Fiber.yield "пауза 1"
  Fiber.yield "пауза 2"
  "завершено"
end

puts f.resume  # => пауза 1
puts f.resume  # => пауза 2
puts f.resume  # => завершено
```

`Fiber` сохраняет место выполнения при `Fiber.yield` и продолжает работу при следующем `resume`. Это механизм передачи управления, а не автоматическая асинхронность или ленивое вычисление. В частности, внешняя итерация через `Enumerator#next` может использовать Fiber, чтобы приостановить обход между значениями.

---

## 🧬 Генератор через Enumerator.new

```ruby
e = Enumerator.new do |yielder|
  yielder << 1
  yielder << 2
  yielder << 3
end

p e.to_a # => [1, 2, 3]
```

`yielder` — объект класса `Enumerator::Yielder`. Через `<<` генератор отдаёт значения при обходе; при создании `e` его блок ещё не выполняется.

---

## 📌 Сравнение

| Инструмент | Что делает | Когда полезен |
| ---------- | ---------- | ------------- |
| `each` с блоком | Сразу обходит элементы | Когда нужно обработать всю коллекцию |
| `Enumerator` | Позволяет отложить обход или получать значения через `next` | Когда обходом нужно управлять извне |
| `Enumerator::Lazy` | Откладывает обработку в цепочке методов | Когда нужны лишь некоторые результаты, в том числе из бесконечной последовательности |
| `Fiber` | Приостанавливает и возобновляет выполнение | Когда нужна явная передача управления |

---

## 🧨 Вопрос на собесе

```ruby
enum = Enumerator.new do |y|
  3.times { |i| y << i }
end

puts enum.next  # => 0
puts enum.next  # => 1
puts enum.next  # => 2
puts enum.next  # вызывает исключение StopIteration
```

Первые три вызова печатают `0`, `1` и `2`. Четвёртый не печатает значение: когда элементы закончились, `next` вызывает `StopIteration`.

---

## 🧠 Почему это важно?

* **Enumerator** позволяет передать обход или запрашивать значения по одному.
* **Lazy** помогает не обрабатывать элементы, которые не понадобятся. Это полезно для больших и бесконечных последовательностей, но не означает, что данные вообще не занимают память.
* **Fiber** даёт механизм кооперативной передачи управления. Сам по себе он не делает блокирующий код неблокирующим.

---

## 💡 Пример: обработка большого CSV лениво

```ruby
require 'csv'

rows = CSV.foreach('big.csv')

admins = rows.lazy
             .select { |row| row[1] == 'admin' }
             .first(10)
```

`CSV.foreach` без блока возвращает перечислитель. Цепочка читает и разбирает записи, пока не найдёт десять подходящих; весь файл заранее в память не загружается. При этом разобранные записи и массив результатов занимают память. В отличие от разбора каждой строки через `CSV.parse_line`, такой вариант подходит и для CSV-записей с переносами строк внутри кавычек.

---

🔚 **Вывод:** `Enumerator` управляет обходом, `Lazy` откладывает обработку элементов в цепочке, а `Fiber` передаёт управление между участками кода. Выбирайте их по задаче: ленивость помогает избежать лишней работы, но не заменяет понимания того, когда и какие данные читаются.
