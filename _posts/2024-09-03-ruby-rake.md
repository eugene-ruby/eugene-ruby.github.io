Rake помогает автоматизировать повторяющиеся действия в Ruby-проекте: от очистки файлов и запуска тестов до отчётов и обслуживания данных. Разберём задачи, зависимости и аргументы, а затем посмотрим, как запускать задачи вместе с Rails и внешними инструментами.

---

## 🧰 Почему Rake — это не только `db:migrate`

В Rails-проекте команда `rake -T` показывает задачи с описаниями. Среди них можно встретить:
```bash
rake db:migrate      # Применить миграции
rake db:seed         # Загрузить данные из seeds.rb
```

Но Rake не ограничивается задачами для базы данных: он позволяет описывать собственные действия и зависимости между ними.

---

## 🔧 Базовый пример: задача для очистки кэша

Если кэш вашего приложения действительно хранится в `tmp/cache`, задачу для удаления содержимого каталога можно положить в `lib/tasks/cache.rake`:
```ruby
require 'fileutils'

desc "Удаляет содержимое tmp/cache"
task :clear_cache do
  puts "Удаляем файлы кэша..."
  if Dir.exist?('tmp/cache')
    entries = Dir.children('tmp/cache').map { |name| File.join('tmp/cache', name) }
    FileUtils.rm_rf(entries)
  end
  puts "Готово!"
end
```

Запуск из каталога проекта:
```bash
bundle exec rake clear_cache
```

Задача удаляет и скрытые файлы внутри `tmp/cache`, но сохраняет сам каталог. Если приложение использует другое хранилище кэша, эта задача его не очистит.

## 🧩 Продвинутые фишки

### 1. Зависимости между задачами
```ruby
task :build => [:compile, :test] do
  puts "Сборка завершена!"
end
```

Rake запустит `compile` и `test` перед блоком `build`. Обе зависимые задачи должны быть определены в проекте; если одна завершится ошибкой, до сообщения о завершении сборки дело не дойдёт.

### 2. Аргументы
```ruby
task :greet, [:name] do |_task, args|
  puts "Привет, #{args.name}!"
end
```
Вызов: `bundle exec rake 'greet[Иван]'`. Кавычки защищают квадратные скобки от обработки оболочкой.

### 3. Использование Rails-окружения
```ruby
task :heavy_report => :environment do  # Загружает Rails-окружение
  User.find_each { |u| puts u.email }
end
```

Зависимость `:environment` нужна, когда задача обращается к моделям и другим компонентам Rails. Такой отчёт выводит адреса пользователей в стандартный вывод — учитывайте это при работе с логами и персональными данными.

## 💼 Реальные кейсы из практики

### 1. **Ежедневный отчёт в Slack**
```ruby
task :daily_stats => :environment do
  today = Time.zone.today
  stats = {
    new_users: User.where(created_at: today.all_day).count,
    payments_total: Payment.where(created_at: today.all_day).sum(:amount)
  }

  SlackNotifier.new.post("📊 Отчёт за #{today}: #{stats.to_json}")
end
```

Здесь обе величины считаются за текущий день в часовом поясе приложения. `SlackNotifier` — предполагаемый сервис проекта, его нужно реализовать отдельно. Сумма всех записей `Payment` не обязательно равна выручке: если у платежей есть статусы, для финансового отчёта потребуется соответствующий фильтр.

### 2. **Массовый фикс данных** (когда миграция не подходит)
```ruby
task :fix_legacy_emails => :environment do
  User.where("email LIKE '%пример%'").find_each do |user|
    user.update!(email: user.email.gsub('пример', 'example'))
  end
end
```

Задача изменяет сохранённые адреса. Перед запуском на рабочих данных проверьте выборку и ожидаемые замены, предусмотрите резервную копию и учитывайте ограничения уникальности: `update!` остановит задачу при ошибке сохранения. Такой скрипт подходит только для конкретного, проверенного правила исправления.

### 3. **Проверка целостности данных**
```ruby
task :check_orphaned_records => :environment do
  Post.left_joins(:user).where(users: { id: nil }).find_each do |post|
    puts "Пост #{post.id} без пользователя!"
  end
end
```

Задача ищет посты, для которых соединение с пользователем не нашло строку. В результат также попадут записи с пустым `user_id`, если он допускается схемой. При обязательном внешнем ключе на уровне базы такие записи обычно не удастся создать штатным способом.

## 💣 Антипаттерны

1. **Гигантские rake-файлы**  
   Не складывайте всю логику в один файл. Разделяйте задачи по назначению:
   ```
   lib/tasks/
     ├── db.rake
     ├── reports.rake
     └── maintenance.rake
   ```

2. **Скрытые ошибки**  
   Не перехватывайте исключение только ради сообщения об ошибке: необработанное исключение уже завершит Rake с ненулевым кодом, что важно для CI/CD. Если добавляете контекст, пробрасывайте ошибку дальше:
   ```ruby
   task :dangerous do
     # Код задачи
   rescue StandardError => e
     warn "Ошибка в dangerous: #{e.message}"
     raise
   end
   ```

3. **Задачи без описания**  
   `desc` помогает найти назначение задачи через `rake -T`:
   ```ruby
   # Без описания задача не появится в rake -T:
   task :mystery_task

   # С описанием:
   desc "Генерирует CSV-отчёт по платежам"
   task :generate_payments_report
   ```

## 🛠 Интеграция с современным стеком

### 1. **Docker + Rake**
Если образ уже содержит приложение, его зависимости и конфигурацию, задачу можно сделать командой контейнера:
```dockerfile
WORKDIR /app
CMD ["bundle", "exec", "rake", "daily_stats"]
```

Один только `COPY lib/tasks /app/lib/tasks` для запуска Rails-задачи недостаточен: ей нужны код приложения, зависимости и доступ к используемым сервисам. `CMD` запускает задачу при старте контейнера, но не создаёт расписание.

### 2. **CI/CD (GitLab example)**
```yaml
run_reports:
  script:
    - bundle exec rake daily_stats
  only:
    - schedules
```

Этот пример запускает определённую выше задачу `daily_stats` в запланированном pipeline GitLab. Само расписание настраивается отдельно; окружению CI также понадобятся зависимости приложения и доступ к сервисам, которые использует задача.

### 3. **Мониторинг через Healthchecks.io**
```ruby
task :cron_job do
  require 'net/http'

  start_response = Net::HTTP.get_response(URI('https://hc-ping.com/your-uuid/start'))
  raise "Не удалось сообщить о старте: #{start_response.code}" unless start_response.is_a?(Net::HTTPSuccess)

  # Основная логика задачи

  success_response = Net::HTTP.get_response(URI('https://hc-ping.com/your-uuid'))
  raise "Не удалось сообщить об успехе: #{success_response.code}" unless success_response.is_a?(Net::HTTPSuccess)
end
```

Замените `your-uuid` адресом своей проверки. Сигнал об успехе отправляется только после основной работы. Для контроля пропущенных запусков проверке нужно задать ожидаемое расписание в Healthchecks.io, а саму задачу запускать внешним планировщиком. В примере основная логика обозначена комментарием — её нужно добавить.

## 🎯 Вывод

Rake подходит для повторяемых действий в проекте: очистки файлов, обслуживания данных, отчётов и проверок. Он описывает и запускает задачи, а расписание, контейнер или CI обеспечивают их запуск в нужном окружении.

Начните с `bundle exec rake -T`: возможно, нужная задача уже есть в проекте.
